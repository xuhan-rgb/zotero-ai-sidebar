Zotero AI Sidebar · Web Agent

把回答交给 ChatGPT 网页版，减少 API 按 token 计费

核心不是让模型少读 token，而是让 Zotero 只负责整理必要上下文，回答过程转移到已登录的 ChatGPT Web。下面比较稳定的半自动交接与体验更完整、但更脆弱的全自动网页代理。

目标
保留 Zotero 论文上下文能力
降低 API token 费用

共同的数据流

只发送回答所需的选区、提问和精简论文线索，不默认搬运整篇 PDF 或全部聊天历史。

返回 Zotero

把最终回答导回原对话；保留来源对话、问题和引用信息，之后可继续写入笔记。

本地边界：PDF 全文、Reader 状态、笔记写入和引用定位由 Zotero 插件管理。
网页边界：只接收用户确认发送的文本；网页端不能直接调用 Zotero 本地工具。
✓ 推荐第一阶段

方案 A：半自动交接

Zotero 生成上下文，用户一键复制/打开 ChatGPT，回答完成后再导回。自动化较少，但最稳定。

  1. 1在 Zotero 点击“交给 ChatGPT Web”，预览即将发送的精简上下文。
  2. 2复制 Prompt 并打开指定 ChatGPT 对话；用户粘贴后发送。
  3. 3复制最终回答，回到 Zotero 点击“导入 Web 回答”。
  4. 4插件把回答记录到原对话，并允许继续写入笔记或创建分支。
稳定性高
操作成本两次复制
维护成本低
可选第二阶段

方案 B：全自动 Web Agent

由浏览器扩展或本地自动化桥接 ChatGPT 页面：自动提交 Prompt、等待回答并写回 Zotero。

  1. 1Zotero 将任务写入本机桥接队列，并携带一次性任务 ID。
  2. 2浏览器扩展在已登录的 ChatGPT 页面创建或选择对话并发送。
  3. 3监听页面回答完成状态，提取最终回复与来源链接。
  4. 4通过本机桥接把结果送回 Zotero，并匹配原对话。
稳定性较低
操作成本最低
维护成本高

推荐落地顺序

先实现方案 A，验证“精简上下文 → ChatGPT Web → 导回 Zotero”的质量和节费效果；只有当每天的复制操作确实成为主要负担，再增加方案 B 的浏览器扩展与本机桥接。两阶段共用同一个上下文打包格式，因此前期工作不会浪费。

重要限制：ChatGPT 网页不能直接读取 Zotero 本地 PDF、调用本地 arXiv/PDF 工具或写笔记；这些内容必须先由插件提取为文本。全自动方案还依赖网页 DOM、登录状态和页面行为，网页更新后可能需要维护。
第一阶段上下文预览、复制并打开网页、导入回答
发送默认值问题 + 显式选区 + 标题/摘要；全文按需
历史策略默认只携带上一轮；需要时切换完整上下文
隐私策略发送前可核对；不自动上传整个 PDF
第二阶段浏览器扩展 + localhost 任务桥接 + 结果回传
