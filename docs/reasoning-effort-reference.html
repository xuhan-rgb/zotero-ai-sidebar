配置原则：不要统一固定成 Low / Medium / High / XHigh，也不要统一默认最高档。“使用服务商默认值”通常意味着省略参数，“关闭思考”需要模型支持明确的关闭方式，两者必须分开。
适配状态（2026-09-29）：已在配置详情加入按模型独立保存的推理强度选择，并共用模型能力规则生成选项与请求参数；主聊天底栏和 Quick Ask 使用同一规则；底栏直接显示当前档位，修改后立即保存到本地。未保存过选择时使用均衡默认值：GPT / Claude 为 Medium，DeepSeek 为 High。未知模型不发送推理参数，已保存的选择优先。下方第 03 表保留适配前问题作为变更依据；第 04 表中的默认值建议不是对既有配置的强制重置。查看当前能力规则。

04 · 默认策略与界面建议

产品配置建议；未在本项目进行质量、延迟或费用对比实验
场景 / 控件建议依据与边界
GPT 论文问答medium 作为起点；复杂推导、多论文综合再评估 high。xhigh / max 留给有明确收益的任务。官方指南建议研究型工作从 medium 或更高档评估；不表示最高档总是更好。
Claude 默认策略Sonnet 4.6 多数应用从 medium 开始；Opus 4.7 能力敏感任务用 high，编程和代理任务评估 xhigh。官方建议因模型而异，不统一降成同一个默认值。
DeepSeek 默认策略简单任务 low；日常 Agent 任务 high；复杂任务 max。官方正式版建议；旧文档中的两档配置不再代表当前完整能力。
配置详情布局选定模型后显示该模型的有效强度；服务商默认单独列出；支持时再提供关闭选项。基于各模型支持集合不同的产品建议；服务商默认不等于关闭。
配置保存与迁移建议按模型保存；同步、导出和导入保留选择；保留已有合法设置，不静默全部重置为新默认值。项目配置设计建议；实施时需验证持久化及旧数据兼容性。
Reasoning Summary保留为独立选项，中文标注“推理摘要”。控制摘要呈现，不应替代“推理强度”入口。

核对方式：本地源码、Git 历史及官方公开文档。未调用付费模型接口，未执行实时 UI 或截图验证。文档和服务商能力可能更新，实施时应重新核对目标模型与 endpoint。此 HTML 可离线打开；官方来源链接需要联网。
