WEB 底栏布局优化方案

目标是消除齿轮按钮的语义歧义，让当前服务与账号入口形成稳定组合，同时减少窄侧边栏中的拥挤和裁切风险。

推荐方案

移除常驻齿轮，把第三方网页管理并入服务菜单

为什么这样更合理

  • ChatGPT 和 DeepSeek 不需要第三方网页齿轮，常驻显示会造成误解。
  • 服务选择与服务管理集中在同一个入口，操作对象一致。
  • “账号”始终紧跟当前服务，只处理登录和浏览器显隐。
  • 减少一个底栏按钮，降低窄窗口下的挤压和裁切概率。
  • 不会触碰发送、增量同步、附件上传或会话恢复代码。

交互规则

  1. 选择 ChatGPT、DeepSeek 或已有自定义服务时，正常切换当前服务。
  2. 选择“管理第三方网页…”时打开现有配置窗口，但不改变当前服务。
  3. 保存新服务后刷新服务列表，并保持此前选择，除非用户主动选择新服务。
  4. “账号”按钮只配置当前服务的登录以及“对话时隐藏浏览器”选项。
  5. 插件不自动切换网页的快速、深度思考或智能搜索状态。

操作流程

1. 选择服务 用户打开 ChatGPT 下拉菜单。
2. 管理服务 点击“管理第三方网页…”，当前服务保持不变。
3. 保存配置 新增、编辑或删除自定义网址，列表立即更新。
4. 配置账号 回到底栏点击“账号”，完成当前服务登录和显隐设置。

稳定性边界

  • 仅调整 WEB 底栏 DOM 顺序和管理入口。
  • 不修改 Web Agent 协议、任务队列和回答刷新逻辑。
  • 不清空当前会话、账号状态或自定义服务配置。
  • 管理菜单项不是实际服务，点击后必须恢复原选择值。
  • 键盘选择和取消配置窗口后也必须保持当前服务。

验收标准

  • ChatGPT、DeepSeek 和自定义服务均可正常切换。
  • 打开管理窗口不会误切换服务或新建会话。
  • 新增、编辑、删除服务后菜单立即同步。
  • 账号按钮始终指向当前服务。
  • 窄侧边栏中所有控件完整可见。
  • WEB 发送、附件和增量刷新测试保持通过。

备选方案（不推荐）

仅把顺序改为 服务选择 → 账号 → 齿轮。它改动最小，但齿轮用途仍不直观，并继续占用底栏空间；适合作为低风险临时修复，不适合作为最终布局。
