## 1. 5 分钟上手

### Step 1 · 配置第一个模型预设

打开 Zotero `工具 (Tools) → 插件 (Plugins)`，点 Zotero AI Sidebar 的 ⚙️ 进入设置；或者直接打开侧边栏，第一次没有任何预设时会自动进入"添加预设"状态。

最少需要填四项：

| 字段 | 说明 |
|---|---|
| Provider | `anthropic` / `openai` / OpenAI 兼容的任意 endpoint |
| API key | 保存在 Zotero prefs；只会随*你自己的* WebDAV `state.json` 或配置导出文件离开本机——不会发给 zotero.org 或第三方 |
| Base URL | 官方端点或自托管反向代理 |
| Model | 该端点支持的任意 model id（如 `claude-opus-4-7`、`gpt-5`） |

填完点 **测试连接**——失败会立刻报错。成功后保存预设。

> 可以保存多个预设；侧边栏底部有一个切换器，对话中途可以换模型。

### Step 2 · 打开侧边栏

侧边栏在 Zotero **条目面板 (Item Pane) / Reader 上下文面板**里以"AI 对话"标签显示。

在主窗口选中任意一篇论文，AI 对话面板就会绑定到这条论文——后续聊天历史、上下文、笔记都按论文分别保存。

### Step 3 · 问第一个问题

最简单的入门提问：

```
帮我用 5 行总结这篇论文，并指出它的核心创新和最大局限。
```

按回车或点 **发送**。如果当前论文有 PDF，模型会自动调用 `zotero_get_current_item`（拿元数据 + 摘要）和 `zotero_get_full_pdf` / `zotero_search_pdf`（拿正文）。**整个工具循环是模型自己决定的，本地不做关键词路由。**

### Step 4 · 看 AI 用了哪些工具

每条 AI 回答上方会展示**思考块**和**工具调用 trace**：

- 思考块默认折叠，点开能看到模型的 reasoning 摘要（取决于 provider 是否提供）。
- Trace 块显示模型这一轮调用了哪些 `zotero_*` / `paper_*` 工具，以及每次调用的参数和返回。

`★ 提示：如果发现 AI 回答凭空发挥，先看 trace 是否有读 PDF 的工具调用。没有的话多半是 max tool iterations 太低或当前 item 没绑定 PDF 附件。`

### Step 5 · 把回答存进笔记

两种方式：

1. **手动**——把鼠标悬到 AI 消息上，点 "复制" 或 "保存到笔记"（按 sidebar 配置，按钮位置和文案可调）。
2. **让 AI 自己写**——直接对模型说"把刚才的总结追加到这条论文的笔记里"。模型会调用 `zotero_append_to_note`，没有子笔记时自动创建。

至此一次完整的"读论文 → AI 解读 → 沉淀进 Zotero"闭环已经跑完。

## 2. 常见场景

### 2.1 让 AI 解读章节或选区

控制 AI 看什么的两种方式：

**默认整篇论文都在上下文里**——composer 旁的 `📄 原文` toggle 默认开启，问任何问题模型都能看到全文。适合"总结这篇论文"、"作者的贡献是什么"、"跟相关工作的对比"这种全局问题。

**想聚焦某一段**：在 Reader 里用鼠标选中一段，composer 上方出现**选中片段 chip**（带字符数预览）。然后正常提问——选区会**叠加**在固定的全文上下文之上，模型既知道周围背景又能聚焦在你高亮的地方。

**想只看选区（不带全文）**：点 `📄 原文` 关闭固定——会弹一次确认对话框说明权衡。开关按论文记忆。

**只升级这一轮**：composer 上方的 `+ 本轮原文` toggle 仅对当前提问升级到全文，不改全局设置。

**注意：**
- 关闭 `原文` 可以省 token，但模型可能漏掉全局上下文（"这篇文章结论是什么"在 `原文` 关闭时可能答不全）。
- 选中片段 chip 不会自动消失——用完点 × 关掉。
- PDF 选区变化时 sidebar 不会重新渲染整页；chip 是唯一的视觉信号。

### 2.2 在 PDF 上沉浸式翻译（沉浸模式）

适用场景：第一次读非母语论文、想快速建立全文理解。

1. 在 Reader 打开 PDF，点侧边栏工具栏的 **沉浸** 按钮进入沉浸模式。鼠标划过句子会出现“在读高亮”。
2. **点击**任意一句即在原句旁就地弹出译文卡（原文 + 译，最省 token）；也可以**选中（或悬停）**某句后按 **快捷翻译键（默认空格）** 直接翻这一句。
3. 卡内可切换 **逐句对照**（一行英文一行中文）、**重点词对应**、**结合上下句**、**自适应宽度**；底部能 **💾 保存** 把当前译文存成 Zotero 高亮批注（该句已有批注则直接显示、不重译），也能继续 **追问** 让 AI 解释 / 举例。
4. **Enter** 翻到下一句、**Shift+Enter** 上一句，连续读完整页 / 整篇；按 **/** 把光标移进卡底「追问」框（Enter 已用于切句）；按 **h** 收起工具栏只留输入框；**Esc** 关掉卡片后该句仍标为「在读高亮」，可继续切句。
5. 再点一次 **沉浸** 按钮退出，PDF 恢复正常浏览。

可调项与快捷键见 [3.5 PDF 沉浸式翻译](#35-pdf-沉浸式翻译)。

### 2.3 让 AI 给 PDF 加高亮/批注

模型可以**真正写入** Zotero 注释，而不只是文字回答。这一类工具默认在普通模式下被拦截，**需要审批或开启 YOLO 模式**。

写类工具：

- `zotero_add_annotation_to_selection`：把当前 PDF 选区高亮成指定颜色 + 备注
- `zotero_add_text_annotation_to_selection`：在选区位置加文本批注
- `zotero_annotate_passage`：模型在更大段落里自己挑句子高亮（多句批量）

典型 prompt：

```
请你通读 §3 方法部分，把"问题陈述/方法步骤/数据集/结果"四类信息分别用不同颜色高亮标出。
```

模型会先用 `zotero_search_pdf` 或 `zotero_read_pdf_range` 取范围，然后调用高亮工具。每次写入都会在 trace 里**显式标注**，便于事后核对或撤销。

颜色映射规则可在 [3.9 PDF 高亮颜色 rubric](#39-pdf-高亮颜色-rubric) 自定义。

使用 **WEB 模式**时，点 **🔖 全文重点**会把论文上下文交给当前网页模型，并要求它在正常回答后附带结构化标注清单。侧边栏会保留网页模型的完整回答；即使网页把清单包在 JSON 代码块里也能识别，再用本地算法把逐字原句定位到当前 PDF，显示可预览的“PDF 标注草稿”。保存前可先预览或重新定位。**解释选区**也复用这条流程：网页回答包含`建议注释`时，可把建议直接用于当前选区。只有显式点击保存后才会写入 Zotero；这一流程不调用模型 API，也不改变 API 模式原有的工具调用、审批或 YOLO 行为。

### 2.4 用 Slash 命令检索 arXiv 或 Web

在 composer 输入 `/` 会弹出可选命令。两个内置命令：

| 命令 | 用法 | 行为 |
|---|---|---|
| `/arxiv-search` | `/arxiv-search <query 或 arXiv URL>` | 告诉模型用户明确要查/分析 arXiv——模型自己选最合适的工具：通用 arXiv 检索，或者当前 item 已缓存 LaTeX 源时走更精准的 arXiv 源工具 |
| `/web-search` | `/web-search <query>` | 调用内建 web 搜索工具（需要在 provider 端开启） |

Slash 命令不在本地做业务逻辑，只是把"用户明确选了这个动作"注入 prompt，由模型决定怎么调工具。

### 2.5 把回答沉淀到论文笔记

笔记面板设计为**和 AI 聊天独立的工作区**：开/关、编辑、保存都不会影响聊天状态、流式输出或 composer 草稿。

- **手动写**：在 Reader 旁边打开笔记面板，直接富文本编辑（用的是 Zotero 官方 EditorInstance，所以 Enter/退格/列表/链接行为和 Zotero 主笔记一致）。
- **AI 写**：让模型调用 `zotero_append_to_note`，自动追加到当前论文的子笔记；没有子笔记时**自动创建一个**。
- **混合**：先让 AI 总结再追加，然后人工调整措辞——和写代码 review 一样。

### 2.6 读 arXiv 论文：精确公式 / 插图 / 表格

对 arXiv 论文，插件会自动下载 LaTeX 源码并从源码读，而不是 PDF 文本层。公式以原始 LaTeX 抵达模型，不再变成 `f l θ` 这种被压扁的碎片。

**判断方式**：侧边栏论文标题旁出现 `LaTeX 源` 徽章 = 当前在源码模式。

**怎么用：**

- **按编号问公式** —— "Equation (3) 怎么理解？" / "解释一下 Eq. 5。" 插件取该公式的精确 LaTeX。
- **按编号问插图** —— "Figure 2 在讲什么？" 插图直接显示在对话气泡里，后续轮（"那张图右下角是什么"）多模态模型仍然能看到这张图。
- **按编号问表格** —— "Table 1 说明了什么？" 插件取表格源码。
- **按名字问章节** —— "解释 Method 这一节" 插件只取这一节，不发整篇。

**注意：**
- 首次问某篇 arXiv 论文会多花几秒——源码在下载和缓存。
- 用**编号**（"Figure 2"、"Eq. 3"、"Table 1"），不要用内容描述（"那张画 loss 曲线的图"）。查找按编号/标签走。
- 非常老的论文或作者未公开源码的情况会静默回退到 PDF 流程——你的提问方式不用变。

机制细节见 [§3.13](#313-arxiv-latex-源模式)。

### 2.7 一眼看懂整篇论文（全文总览）

适用场景：在啃 PDF 之前先判断哪几章值得细读，并跨会话、跨设备记住自己读到哪。

全文总览是笔记列里的 **总览** 视图——笔记列头部三个标签之一（`AI 笔记` / `阅读路线` / `总览`）。它**不是笔记**，而是一张生成出来的、可点击的论文地图，跟 Reader 并排显示。

1. 打开笔记列（工具栏 **打开笔记**），切到 **总览** 标签，点右上角 **生成总览**。模型会先调 `zotero_outline_pdf`（一个便宜的全文骨架，不发整篇 PDF），再调 `render_paper_overview`。
2. 你会得到：2–4 句**核心讲述**、一份**按阶段分组的章节骨架**（动机与背景 / 方法 / 验证与结论），每节带一句 ≤30 字的 gist 和 **创新 / 效果锚点** 标记，可折叠子章节，外加一张折叠的结构**流程图**。
3. **点任意章节即把 PDF 跳到那里。** 有 PDF 内嵌目录时精确跳到该节顶部，没有时回退到文本匹配。
4. 顶部 sticky header 记着你在哪：`↩ 在读 N` 跳回你的在读锚点，`↶ 返回 N` 沿你走过的路回退（同时跳 PDF），**🔒 锁定**让你浏览别的章节而不移动 `在读` 锚点。
5. **`↗ 浏览器`** 把完整总览作为独立 HTML 在系统浏览器打开。总览还会自动保存成该条目的子 HTML 附件，跟着 Zotero 自己的同步走。

**阅读位置会被记住并同步。** 每篇论文的 `在读` 锚点重启后仍在，并随 `state.json`（WebDAV）走。

> **阅读路线（`阅读路线`）** 是它基于笔记的近亲：会变形的路线按钮（`生成路线` → `阅读路线` → `更新路线`）生成一份阅读指南，存进专用的 *AI 阅读路线* 子笔记。重新生成会覆盖 AI 区，但保留你自己的 `「我的补充笔记」`。总览用来*导航*，路线笔记用来*留可编辑的文字*。

**注意：**
- 章节跳转依赖 PDF 目录 / 文本匹配（没有 SyncTeX），所以 PDF 自身目录里没有的章节，落点可能是近似的。
- 非 arXiv 的 PDF 用启发式标题检测；找不到标题时回退到等分窗口（header 显示 `· 估算分段`）。
- 总览按需生成——绝不自动发送整篇 PDF。

### 2.8 跨设备同步聊天和配置（WebDAV）

适用场景：在台式机和笔记本之间想保留一致的聊天历史、prompt 库、UI 设置。

1. 在设置里填 WebDAV 端点（URL、用户名、密码）。坚果云、自建 NextCloud 都可以。
2. **Push** 把当前机器的状态打包成单个 `state.json` 上传。
3. **Pull** 从云端拉回 `state.json` 覆盖本地。
4. **自动同步** 默认关闭；开启后启动时和每 10 分钟自动下载合并再上传。

`state.json` 包含：

- ✅ 聊天线程（每篇论文的对话、思考块、工具 trace、图片元数据）
- ✅ 模型预设**（含 API key）**，以及 UI 设置、Quick prompts、tool/MCP 设置、翻译设置
- ✅ 逐句翻译缓存（已翻译句子的译文缓存）
- ✅ 完整 PDF 批注（高亮 / 下划线 / 笔记 / 墨迹），按 PDF + 批注键匹配，按修改时间 last-write-wins
- ✅ 每篇论文的全文总览和阅读位置（`在读` 锚点）
- ❌ **PDF 文件本身不上传**（PDF 走 Zotero File Sync，独立路径）
- ❌ **WebDAV 账号口令**不会写进 `state.json`

由于 `state.json` 带着你的密钥，这个 WebDAV 端点要由你自己保护——它是你自己的服务器，永远不是 zotero.org 或插件作者。

`★ 三层同步分工`
- `zotero.org`（免费 300MB 元数据）—— 文献库元数据
- WebDAV（你自己的云）—— 一份给 Zotero 内置 File Sync 同步 PDF；另一份（路径不同）由本插件存 `state.json`
- 三者解耦，删除一层不影响另外两层

### 2.9 备份和迁移配置

不想用 WebDAV 也可以走纯导出/导入：

- **导出**：设置里点导出，下载一个 JSON 文件。包含模型预设**（含 API key）**、UI 设置、quick prompts、tool/MCP 设置和翻译设置。
- **导入**：在新机器选择该 JSON——密钥也会一并带过去，无需重填。
- 该文件含密钥，请妥善保管：不要贴到公开 issue 或共享盘。

### 2.10 用 Quick Ask 临时连续追问

适用场景：不想切换或污染当前论文的研究对话，只想临时问几轮；也可以先在 PDF 或全文翻译页选中一段，再围绕它追问。

1. 默认按 `Alt+Q` 打开 Quick Ask。快捷键可在 `设置 → 沉浸阅读 → Quick Ask 临时问答` 中修改；焦点正在输入框内时不会抢键。
2. 如果打开前选中了 PDF 文本或全文翻译原文，Quick Ask 会把该选区作为第一轮参考。没有选区时，模型仍可按需使用只读工具查看当前论文。
3. 输入第一问；回答完成后，底部会出现较紧凑的“继续追问”输入框。后续问题会携带本窗口已经完成的问答，因此可以直接问“为什么”“再举个例子”“这个结论如何验证”。
4. 点顶部的模型名称或“模型设置”，可切换账号、模型和思考强度。首次使用采用当前 AI 对话模型，修改后由 Quick Ask 独立记忆，不会反向修改研究对话或翻译模型。
5. **复制**只复制最后一次回答；**转入研究对话**会把本窗口全部轮次写入当前论文的研究对话，然后关闭 Quick Ask。

Quick Ask 不读取已有研究对话历史，也不调用写入类工具。按 `Esc`、右上角关闭按钮或点击遮罩空白处后，本窗口全部问题和回答都会销毁；重新打开是一个新会话。

### 2.11 阅读 arXiv 全文翻译

当前论文标题旁出现 `LaTeX 源` 徽章时，点旁边的 **全文翻译** 进入重建后的整篇阅读页。该入口依赖 arXiv LaTeX 源；普通 PDF 或没有公开源码的 arXiv 条目不会显示。

- 顶部用 **中英 / 中文 / 英文** 控制语言，用 **左右 / 逐段** 控制版式；“阅读设置”里还能调整原文颜色、字号、行距和段落间距。
- 点进度栏中的模型名称可展开 **账号 / 模型 / 思考强度** 下拉列表。第一次打开时从设置页的“默认翻译模型”继承；在这里修改后，全文翻译会独立记住自己的全局选择，不会改变沉浸阅读默认模型。
- 点 **开始翻译** 翻译尚未完成的段落；中断后显示 **继续翻译**，已有结果不会清空。需要全部重做时用 **重新翻译**。
- 全文翻译页与右侧 AI 对话可以并排使用；在译文或原文中选择文字后，也可以按 `Alt+Q` 打开 Quick Ask 临时连续追问。
- 点 **返回 PDF** 退出全文翻译并回到 Reader。

### 2.12 通过 WEB 模式使用内置网页模型

WEB 模式把真实 AI 网页的回答同步进 Zotero 对话，适合使用网页账号而不是 API Key。API 模式与它完全独立，不需要 Chrome 或伴随进程。

**首次安装（Windows / Linux / macOS）：**

1. 安装 Node.js 20 或更高版本和 Google Chrome。Linux 还需要 `xclip`：

   ```bash
   sudo apt install xclip
   ```

2. 安装 XPI，在输入框底栏选择 **WEB**，选择 **ChatGPT**、**DeepSeek**、**ChatGLM**、**Z.ai** 或 **Kimi**，再点**账号**。
3. 账号窗口会自动检查环境。缺少 Node.js 或 Chrome 时提供官方下载按钮，Linux 缺少 `xclip` 时提供可复制的安装说明；插件不会自动运行安装程序或系统命令。解决依赖后点**重新检查环境**，再按窗口状态选择**安装 / 修复 / 升级 Web Agent**。插件会从当前版本的 GitHub Release 下载预构建运行包，校验大小与 SHA-256，并在协议和健康检查通过后继续；用户电脑不执行 npm。自动下载失败时，可打开或复制窗口提供的链接，用浏览器下载 ZIP 后在同一窗口选择安装。
4. 在临时显示的 Chrome 窗口中完成登录。保留“**对话时在后台隐藏浏览器**”勾选，即可在配置完成后最小化专用浏览器；该选项默认开启。

Web Agent 不单独发布版本，只使用当前 XPI 配套的 ZIP。安装和手动更新时，插件校验 ZIP 的大小与内置 SHA-256，并记录安装摘要；XPI 更新后仅比较一次安装记录，摘要相同则继续使用。正常启动、打开 WEB 和发送消息不会下载运行包、扫描文件或重新计算摘要，只做必要的本机健康检查。旧安装没有摘要记录时，需要安装一次当前配套运行包。更新失败保留原有文件与登录配置，但不会启用不匹配的旧包。

新版 Web Agent 和专用 Chrome 启动时由系统分配空闲端口，避免与 MCP 等插件争用固定端口。Agent 监听成功后会把实际 `port` 写回 Zotero 数据目录下的 `zai-web-agent-config.json`，XPI 自动读取；`cdpPort: 0` 表示 Chrome 自动分配，其实际调试端口记录在专用浏览器配置目录的 `DevToolsActivePort` 中。Zotero 回调继续复用已有 HTTP 服务。正常退出 Zotero 或禁用 AI Sidebar 时，插件请求关闭自己的 Agent；只切换到 API 模式不会中断正在执行的 WEB 任务。旧运行包需要升级后才能获得自动端口分配修复。

**日常使用：**

1. 选择 **WEB** 和目标服务。服务菜单还会列出已保存的自定义站点，最后一项是“**管理第三方网页…**”；打开管理窗口不会改变当前服务。
2. 像普通对话一样提问，按 Enter 或点击发送箭头。两者执行同一套实时账号检查；所选网页未配置或登录已失效时会停止发送，并提示打开**账号**。随后侧边栏依次显示准备、上传、提交、生成、同步进度；网页回答增长时会持续同步，不必等网页完成后才一次性出现。
3. 论文阅读任务会通过网页真实文件输入框自动附加当前论文：有缓存的 LaTeX 主文件时优先发送，否则发送 PDF。arXiv 条目还会附带一份只含章节层级、编号和标题的 TXT 目录，不包含 Zotero 工具说明或章节正文。站点没有可用文件输入框时会明确报错，不会为了剪贴板粘贴而闪现浏览器。
4. 需要标注建议时，可提出**全文重点**或**解释选区**任务。提示词会告诉网页模型返回结构化清单，插件从正常回答中解析并生成本地草稿；保存前应核对匹配页码和原句。
5. 只有网页提供真实附件或可下载 URL 时，生成文件才会出现在 Zotero。正文里的 `sandbox:/...` 只是网页沙盒文字路径，不能当成下载文件。

任务运行中可按 `Esc` 或点击输入框的**停止**按钮取消。已经同步到 Zotero 的部分回答会保留并标记为已取消；重试仍发送到原来的网页服务。网页上的登录、额度、服务器和不支持上传等提示会作为错误回答显示，不会混进正常答案。

Web Agent 使用独立 Chrome 配置目录和随机 localhost bearer token，不读取日常 Chrome 配置。登录、验证码、上传和网页脚本仍需要真实浏览器，所以“隐藏”是最小化，而不是 headless API。Zotero 不切换网页的快速/深度思考/智能搜索开关，以网页当前状态为准。

## 3. 功能手册

### 3.1 模型预设

每个预设是一组完整的"provider + endpoint + 模型 + 参数"，可保存多个、命名区分。

| 字段 | 必填 | 说明 |
|---|---|---|
| Provider | ✓ | `anthropic` / `openai`，决定 SDK 路径 |
| Display name | | 在底栏切换器里看到的名字 |
| API key | ✓ | 保存在本地 prefs；会随你自己的 `state.json` 和配置导出文件一起走，绝不发给 zotero.org / 第三方 |
| Base URL | ✓ | 官方端点或 OpenAI 兼容反向代理 |
| Model | ✓ | model id，如 `claude-opus-4-7`、`gpt-5` |
| Max output tokens | | 输出长度上限 |
| Max tool iterations | | **安全保险丝**——单轮对话允许的工具循环次数。**不是任务路由开关**。设置过低会让 AI 没机会读完 PDF 就被强行截断 |
| Reasoning / Thinking | | 启用 reasoning effort（OpenAI）或 extended thinking（Anthropic）；要求 model 支持 |
| Agent permission mode | | 控制写类工具：默认禁写 / 需审批 / YOLO 直通 |

**测试连接**会发一条最小请求验证 endpoint 与 key。

每个预设独立维护自己的"模型列表"——同一 base URL 下可以快速切换不同 model id。

### 3.4 Slash 命令

在 composer 输入 `/` 触发提示。当前两个内置命令：

| 命令 | 用法 | 作用 |
|---|---|---|
| `/arxiv-search` | `/arxiv-search <query 或 arXiv URL>` | 明示“我要查 / 读 arXiv”。模型自己选最合适的工具：通用 arXiv 检索，或当前 item 已缓存 LaTeX 源时走更精准的 arXiv 源工具 |
| `/web-search` | `/web-search <query>` | 明示“我要联网搜”。模型调用内建 web 搜索工具来回答 |

**是什么** —— slash 命令是**明示快捷指令，不是开关，也不在本地跑任何逻辑**。它只把“用户明确选了这个动作”注入到你这条消息里，具体调哪个工具仍由模型决定。这是本插件 Codex 风格的核心约束：**没有本地关键词路由替你猜意图**。

**什么时候用** —— 多数时候**用不上**：问题只要够明确，模型自己就会选对工具（例如开了「联网」开关后，问实时类问题模型会自己去搜）。它的价值在**消歧**——当问题相对当前论文语境比较跑题或模糊时（典型如在论文页面里突然问天气），模型可能先犹豫“该不该做、用哪个工具”，这时一个明示的 `/web-search` 让它**直接执行**：少绕弯、少重复调用、更省 token。

**注意**

- `/web-search` **本身不开启联网**。真正的总闸是 composer 左下角的「联网」开关（或设置里的 Web search 模式）。开关没开时，即使打了 `/web-search`，模型也只会**如实告诉你“联网未启用”**，不会假装搜索。
- 内建 web 搜索是 **provider 侧的 hosted 工具**；若你的 Base URL 不支持它，开了开关也可能搜不动。
- 不带参数直接发命令时，模型会让你先补一个查询。

### 3.5 PDF 沉浸式翻译

设置页“沉浸阅读”中的 **默认翻译模型** 决定沉浸卡使用的账号、模型和思考程度。arXiv 全文翻译第一次使用时也从这里继承，但之后可在全文翻译页顶部独立修改并记忆；两边互不覆盖。结果位置、翻译框大小和下表选项用于沉浸卡。

| 设置（沉浸阅读） | 说明 |
|---|---|
| 单击直接出卡 | 关闭则改为先弹「问 AI / 译」选择条 |
| 结合上下句 | 翻译时带上前后各一句作上下文，更准 |
| 重点词对应 | 译文里高亮原文 ↔ 中文关键词对，悬停互相点亮 |
| 下一句 / 上一句快捷键 | 默认 `Enter` / `Shift+Enter`，可改 |
| 选区快捷翻译键 | 默认空格；只在“有在读高亮 / 选区”时才拦截，没有时空格照常翻页 |
| 聚焦追问键 | 默认 `/`；卡片开着时把光标移进「追问」框（Enter 已用于切句） |
| 收起工具栏键 | 默认 `h`；把卡片的信息栏 + 底部按钮行折叠到只剩输入框 |

卡内还能临时切「逐句对照」「自适应宽度」。`Esc` 关卡后该句回到「在读高亮」，可继续切句。

卡片可用 💾 把当前译文保存为 Zotero 高亮批注；若该句已存在批注，再次打开会直接显示已存的笔记而不重新翻译，保存时按 key upsert（同一句不会叠出重复高亮）。

进入沉浸模式后 Zotero 原生选区菜单会被隐藏，避免和翻译卡冲突，退出自动恢复。翻译结果按句子内容哈希缓存，同一句重复翻不重复发请求。

### 3.6 Quick prompts（快速提示词）

在 composer 旁边可以放若干**一键发送按钮**——比如"总结全文"、"讲一下方法部分"、"找出实验数据"。每个按钮的文案、对应的 prompt 模板都在设置里编辑。

适合把高频提问做成一键操作。

### 3.7 笔记编辑面板

目标布局：`PDF Reader | 笔记面板 | AI 聊天`。

- **底层引擎**：Zotero 官方 `<note-editor>` / `EditorInstance`。富文本（标题、列表、链接、内联代码、引用）行为和 Zotero 主笔记一致。
- **不与聊天耦合**：开/关/编辑笔记不会触发 sidebar 重渲染、不会重置 composer 草稿、不会打断流式输出。
- **AI 写入**：模型调用 `zotero_append_to_note`，会自动找到（或创建）当前 item 的子笔记，把内容追加到末尾。
- **三个标签**：笔记列头部在 `AI 笔记`（聊天「写入笔记」默认追加到这里）、`阅读路线`（专用 *AI 阅读路线* 阅读指南笔记；按钮在 `生成路线` → `阅读路线` → `更新路线` 之间变形）、`总览`（全文总览视图，见 [§3.14](#314-全文总览与阅读路线)）之间切换。重新生成路线会覆盖 AI 区，但保留你自己的 `「我的补充笔记」`。

### 3.8 截图与多模态输入

工具栏的 **截图** 按钮触发 PDF / Reader 区域的截图，截图会作为图片附件挂在 composer 上。截图按钮在 Linux（`gnome-screenshot` / `flameshot` / `import`）和 Windows（Snip & Sketch 区域选择）上可用；其他平台请改用拖拽图片。任意平台也都可以直接把图片拖到 composer。

发送时图片**真的会**作为 multimodal input 传给 provider（不只是本地展示）——模型必须支持 vision 才有效（Claude 3+, GPT-4o/5 系列等）。

**arXiv 插图同理**——从 arXiv 源拉来的插图会出现在对话里，并且持续作为多模态输入挂着（你接着问"那张图右下角是什么"时，vision 模型仍然能看到这张图）。

### 3.9 PDF 高亮颜色 rubric

Zotero 默认六色分别由 hex 表示。本插件把每种颜色对应到一个语义标签（背景/问题/方法/数据集/结果/...），并把这套 rubric 作为自然语言 prompt 注入给模型，让 AI 在调用 `zotero_add_annotation_to_selection` 时自己选颜色。

可在设置里**改写 rubric**，比如做文献综述时改成"已知/争议/我的批注/...",AI 会照新规则匹配。

### 3.10 WebDAV 云同步

| 项 | 行为 |
|---|---|
| 端点 | URL + 用户名 + 密码（建议用应用密码） |
| 推送 | Push：把本机当前 `state.json` 上传 |
| 拉取 | Pull：把云端 `state.json` 下载并覆盖本机 |
| 冲突 | 没有自动 merge——后写覆盖先写，谁是 source of truth 由用户掌握 |
| 路径稳定性 | 使用"线程键"做 portable 标识，跨机迁移时不会因 itemID 变化丢线程 |

`★ 提示：和 Zotero 内置 File Sync 走的是不同的 WebDAV 路径，互不干扰。即使共用同一个 WebDAV 账号也安全。`

### 3.11 配置导出 / 导入

| 字段 | 包含 |
|---|---|
| UI 设置（昵称、头像、个性签名、主题、操作按钮位置） | ✅ |
| 模型预设 | ✅ |
| API key（在预设里） | ✅ —— 请妥善保管文件 |
| Quick prompts | ✅ |
| Tool / MCP 设置 | ✅ |
| 翻译设置 | ✅ |
| 聊天历史 | ❌（用 WebDAV 同步） |
| PDF 批注 | ❌（用 WebDAV 同步） |

适合做"换机时把配置带过去，但聊天保留在原机"的场景。

### 3.12 聊天历史

- 每篇论文一条独立线程，绑定到 itemID（跨机靠 portable 线程键迁移）。
- 单条消息保留：文本、思考块（reasoning summary）、工具 trace、图片附件元信息。
- **复制为 Markdown** 两种模式：
  - **Clean**：论文简介 + 对话本身。适合分享、发博客。
  - **Debug**：含完整思考、context trace、PDF 片段、错误日志。适合反馈 bug 或追溯模型决策。

### 3.13 arXiv LaTeX 源模式

对 arXiv 论文，插件会从 LaTeX 源码读取，而不是 PDF 文本层。论文标题旁出现 `LaTeX 源` 徽章就是当前在源码模式。

带来的不同：
- 公式以原始 LaTeX 抵达模型，不再是 PDF 文本层里被压扁的碎片。
- 按编号引用都能精确命中——"Eq. (3)"、"Figure 2"、"Table 1" 都映射到正确对象。

如果当前论文没有可用的 arXiv 源（没有 arXiv ID、作者未公开源码、下载失败），插件会静默回退到 PDF 流程。

### 3.14 全文总览与阅读路线

两种从结构上把握论文的方式，都从笔记列头部进入。

**总览——全文总览地图**（生成出来的视图，不是笔记）：

| 元素 | 含义 |
|---|---|
| `生成总览` / `更新总览` | 右上角按钮。通过 `zotero_outline_pdf` → `render_paper_overview` 生成（或重新生成）地图，不自动发整篇 PDF |
| 核心讲述 | 2–4 句话讲清这篇论文做了什么、贡献是什么 |
| 章节骨架 | 按文档顺序排列，按阶段分组——**动机与背景 / 方法 / 验证与结论**，每节带一句 ≤30 字 gist；子章节可折叠 |
| 创新 / 效果锚点 | 强调标记；`创新` 章节点出*新*在哪，`效果锚点` 标出主要结果 / SOTA |
| 结构流程图 | 一张折叠的 问题 → 方法 → 结果 逻辑图 |
| `↩ 在读 N` | 头部控件：跳回你的在读锚点 |
| `↶ 返回 N` | 沿走过的章节回退（同时跳 PDF） |
| 🔒 / 🔓 锁定 | 浏览别的章节而不移动 `在读` 锚点 |
| `↗ 浏览器` | 把完整总览作为独立 HTML 在系统浏览器打开 |

点章节行即把 PDF 跳到那里——有 PDF 内嵌目录时精确跳到该节顶部，否则回退到文本匹配。地图和 `在读` 锚点按条目存储，自动保存成子 HTML 附件，并随 `state.json` 同步。

**阅读路线——阅读路线笔记**（可编辑的文字）：会变形的路线按钮生成一份阅读指南，存进专用的 *AI 阅读路线* 子笔记。重新生成会覆盖 AI 生成区，但保留你的 `「我的补充笔记」` 部分。

注意：跳转依赖 PDF 目录 / 文本匹配（没有 SyncTeX）；非 arXiv 的 PDF 用启发式标题检测，可能回退到等分窗口（`· 估算分段`）。

### 3.15 API 与 WEB 对话模式

| 控件 | API 模式 | WEB 模式 |
|---|---|---|
| 发送目标 | Zotero 中配置的模型预设 | ChatGPT、DeepSeek、ChatGLM、Z.ai、Kimi 或自定义 ChatGPT-like 网页 |
| 认证方式 | Zotero prefs 中的 API Key | 独立 Chrome 配置中手动登录 |
| 工具能力 | 可使用 Zotero / 模型工具循环 | 同步网页回答，不运行 API 工具循环 |
| 浏览器 | 不使用 | 账号配置完成后默认最小化 |
| 进度 | Provider 流式输出与工具 trace | 五阶段任务进度和持续增长的 DOM 快照 |
| 网页模式 | 由预设参数控制 | 采用网页当前模型/搜索/思考状态，Zotero 不主动切换 |
| 论文上下文 | 用“原文”控制 API prompt 上下文 | 由 WEB 文件上传流程自动附加 |
| 联网控制 | “联网”使用所配置的 API Web Search 能力 | “联网”禁用；使用网页自身的搜索开关 |

WEB 底栏只保留两个紧密关联的控件：

- **智谱网页入口**：`ChatGLM（chatglm.cn，风控受限）` 保留国内站入口；当前版本在已复现环境中仍会验证失败。`Z.ai（chat.z.ai）` 是单独入口，账号登录和网页会话分别保存；真实站点完整对话尚未验证。
- **服务菜单**：切换 ChatGPT、DeepSeek、ChatGLM、Z.ai、Kimi 和已保存的自定义站点。最后的“管理第三方网页…”只打开 URL 管理，并恢复此前选中的服务。旧版保存的 `kimi.com` 自定义项会自动迁移为内置 Kimi，避免重复入口。
- **账号**：打开当前服务登录页，并配置专用浏览器在对话时是否保持最小化。
- **发送**：Enter 与箭头走同一条发送路径，并在提交前实时检查账号状态。
- Zotero 不再提供快速/深度思考/智能搜索开关；需要修改时，在账号窗口显示网页后直接操作网页控件。

### 3.16 空对话个性签名

打开 `设置 → Zotero AI Sidebar → 显示设置 → AI 个性签名`：

- 每条签名占一个输入行，最多 80 个字符；用 `＋ 添加签名` 新增。
- 使用 `↑` / `↓` 调整显示顺序，使用 `×` 删除单条签名。
- 勾选“在空对话中显示 AI 个性签名”后，签名组显示在空白对话区中央；欢迎语仍留在顶部。
- 鼠标悬停中央签名组时会出现 `×`。点击后只关闭显示，不删除列表；可回到设置页重新勾选。
- 发送第一条消息后签名组立即隐藏；切换到新的空对话或清空当前对话后重新显示。
- 用户修改、清空、关闭或调整顺序后，插件升级不会用新版默认文案覆盖这些配置。
- 旧版以英文分号 `;` 或中文分号 `；` 保存的内容会按原顺序迁移成列表。

默认提供两条提醒：

1. `Why am I reading this paper? Keep the question in sight.`
2. `Answers can be borrowed, but the thinking must be your own.`

## 故障排查

### "WEB 模式提示账号未配置"

点击**账号**，等待专用 Chrome 出现，完成登录并确认网页输入框可编辑。自定义站点必须先通过“管理第三方网页…”添加，再配置账号。

### "WEB 模式一直等待 / 回答不刷新"

先看进度卡是否仍在推进。伴随进程版本过旧时，插件会在提交前拒绝任务；出现协议提示后打开**账号**，根据检测结果点击**安装 / 修复 / 升级 Web Agent**。任务进行中关闭 Zotero 可能保留上次进度卡，但如果 Agent 进程已经停止，并不代表网页仍在后台生成。

需要中断仍在运行的任务时，按 `Esc` 或点击输入框的**停止**按钮。已同步的部分回答会留在对话中并标记为已取消，之后可直接重试，仍会使用当前选中的 WEB 服务。

### "WEB 提问时 Chrome 仍然出现"

点击**账号**并勾选“对话时在后台隐藏浏览器”。隐藏模式上传附件只使用网页真实文件输入框；站点没有该输入框时会报错，而不会聚焦 Chrome 使用剪贴板粘贴。登录和验证码配置仍会有意显示浏览器。

### "API 调用失败 / 401 / 403"

1. 设置里点 **测试连接**，看具体错误码。
2. 检查 base URL 末尾 `/v1` 之类后缀是否正确。
3. 自建反向代理时，确认完整支持 OpenAI Responses API（OpenAI provider）或 Anthropic Messages API（Anthropic provider）的相应字段。

### "AI 没读 PDF / 给的是凭空答案"

1. 确认 Zotero 主面板**确实选中**了一篇有 PDF 附件的条目。
2. 看消息上方 trace——有没有 `zotero_get_current_item` / `zotero_get_full_pdf` 的调用？
3. 如果工具被截断，提高预设的 **Max tool iterations**。
4. Provider 限速时模型可能放弃工具循环，直接答；查看 trace 里有无错误记录。

### "沉浸翻译点了没反应 / 按快捷键不翻译"

1. 必须在 Reader 标签里用，不是 Library 主面板；并确认工具栏 **沉浸** 已开启。
2. 快捷翻译键翻的是“当前在读句”：先让鼠标划过 / 选中某句（出现高亮）再按键；没有高亮时按空格只会翻页。
3. 如果同时开了某些 PDF 标注插件，可能拦截了 click 事件，临时关掉再试。

### "WebDAV 推送失败"

1. URL 末尾要带 `/`。
2. 坚果云、Mailbox 等服务用 **应用专用密码** 而不是登录密码。
3. 服务端权限：写入路径需要可创建子目录。

### "AI 想加批注但被挡住了"

默认禁写。两条解决路径：

- 临时：让 AI 把建议的高亮位置和颜色文本输出，你自己手动加。
- 长期：在该预设里打开 **YOLO 模式** 或对应的 permission mode（仅对该预设生效）。

### "侧边栏在 PDF 选区变化时抖动"

这是设计避免的反模式。如果你遇到，请打开开发者工具看看是不是某个旧版扩展残留——本插件的"选中片段 chip"是显式 UI，不会在 PDF 选区变化时自动重新渲染整个 sidebar。

### "复制按钮丢失思考内容 / 工具调用"

切到 **Debug 复制模式**——Clean 模式刻意只保留论文简介 + 用户/AI 文本，是给分享场景用的。

### "模型总是读整篇论文，但我只想让它看我的选区"

这是 composer 旁 `📄 原文` toggle（默认开启）的行为。点一下关掉，下一轮就只用选区 + 模型主动调用工具取的内容。这个开关按论文记忆。

### "首次问 arXiv 或公式多的论文很慢"

正常现象。插件在为这篇论文建一次性的缓存（arXiv 源码下载，或者非 arXiv 论文的公式修复）。同一篇论文再问就很快了。

### "arXiv 论文里模型找不到 Figure 2 / Equation 3"

引用插图、公式、表格请**用编号**（"Figure 2"、"Eq. 3"、"Table 1"），不要用内容描述（"那张画 loss 曲线的图"）。arXiv 工具按编号/标签查。
