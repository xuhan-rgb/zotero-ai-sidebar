拾取素材时，左侧 PDF 该怎样响应？

进入拾取态（点「素材」按钮，或按 @ 打开素材列表）之后，左侧 PDF 同时还是一个正常的阅读器： 它可以划选文字、可以点注释和超链接。两种身份叠在一起，才有了下面这些取舍。

四个沙盒都可以直接上手试：点空白处、在空白处划选文字、点蓝色素材框、点 [12] 链接。 下方文字会实时告诉你在该方案下发生了什么。

动手试试：点空白 / 划选 / 点框 / 点 [12]
  • 命中框 → 选中素材；空白处点击也一并吞掉，不做任何事。
  • 文字锁是三层的：CSS user-select: none、拒掉 selectstart、以及右侧不接受拾取期间产生的选区。阅读器自己的选择逻辑不经过我们的监听器，光吞 pointerdown 拦不住那一下拖拽。
  • 代价：拾取期间复制不了原文，也点不开注释和链接；空白处点击毫无反馈，容易被当成卡死。

已选定：A（全吞）

  • 决定：拾取态下左侧文字不可选择，空白处点击也不做事 —— 状态唯一，不会出现「正在选公式却选中了一段文字」。
  • 落地一：src/modules/pdf-pick-cursor.ts 在拾取态往阅读器文档注入 .page, .page * { cursor: crosshair; user-select: none }，关闭拾取时整块移除。
  • 落地二：src/modules/sidebar.ts 的 watchFigurePdfPick → onPointerDown 继续吞掉 pointerdown；CSS 锁负责兜住阅读器自己发起的那次拖拽。
  • 落地三：src/modules/figure-picker.ts 的 startPdfWatch / figureAtPoint 不变，命中素材框仍然选中。
  • 落地四（兜底）：万一还是划出了选区，它也不会进到右侧对话。拾取期间 selectstart 被拒、监听器与轮询都不再记录选中的文字，发送时也只用拾取开始前已经存下的选区。
  • 如果以后想放开注释和引用，再把 C 的那行 closest("a[href], .annotationLayer") 提前 return 加回来即可。
const onPointerDown = (event: PointerEvent) => {
  const point = normalizePoint(event, event.target as Node);
  if (!point) return;
  const [pageIndex, x, y] = point;
  onPick(pageIndex, x, y);
  event.preventDefault();
  event.stopPropagation();
};
  • 与方案无关、维持现状：素材来自 LaTeX 源时没有 bbox，压根不进拾取态，点「素材」直接打开列表；列表底部现在也写了这句。
  • 注意：列表开着（按 @ 或点「素材」）也算拾取态，所以这时左侧同样划不中文字，要看原文先把列表关掉。
