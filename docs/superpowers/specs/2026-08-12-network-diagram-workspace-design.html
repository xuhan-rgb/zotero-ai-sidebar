01目标与边界

用户提供一个公开 GitHub 仓库链接。插件联合论文方法章节和固定 commit 下的真实代码生成网络图，并允许在图下方使用独立对话逐步展开、简化和核对。

Repository
仅公开 github.com 仓库，不保存 Token
Conversation
独立网络图对话，复用主对话模型配置
Evidence
节点关联论文章节、代码路径与符号
Revision
每次成功修改生成不可变版本
不克隆仓库、不执行代码、不安装依赖、不下载模型权重；任何生成失败都不能覆盖当前网络图。

03独立 AI 对话

网络图对话与论文主对话分离，但复用当前模型、API、推理强度和联网设置。网络图指令不会污染论文问答历史。

主对话 论文问答、翻译、笔记、注释与研究任务。
网络图优化对话 GitHub 分析、局部展开、简化、证据核对与版本历史。
共享配置 当前模型、API 连接、推理强度与联网能力。

每轮上下文

  • 当前网络图与当前版本；
  • 用户选中的节点与本轮要求；
  • 固定 GitHub commit 与已读取证据索引；
  • 论文相关方法章节；
  • 网络图对话摘要与最近消息。

所有历史消息都保存，但模型调用使用“对话摘要 + 最近消息”，避免多轮优化后上下文无限增长。

04组件架构

仓库读取、证据构建、图修改和版本存储彼此隔离；UI 不直接访问 GitHub，也不直接写总览缓存。

Network Diagram Workspace UI 来源栏 · 网络图画布 · 版本控制 · 依据面板 · 专用对话
↓
Network Diagram Controller 协调首次生成、逐轮优化、状态切换和失败恢复
↓
GitHub Reader URL 校验、commit 固定、目录树、文件预算和本地缓存
Evidence Builder 论文概念、配置、类、forward 与网络节点的映射
Diagram Agent 首次生成、证据申请、结构化图补丁和修改说明
↓
Revision Store 完整快照、父版本、对话、当前与最新版本指针
WebDAV Adapter 同步版本、对话、来源和证据定位，不同步源码正文
Overview Export 导出最终图与来源，不携带对话、API 配置或源码

05公开 GitHub 仓库读取

通过 GitHub REST API 读取公开资源，不依赖本机 git 或登录状态。同一次分析固定到一个 commit SHA。

1
校验链接 只接受 github.com/{owner}/{repo}，拒绝任意网页和带凭证 URL。
2
固定版本 获取默认分支和当前 commit SHA，后续文件统一按 SHA 读取。
3
读取目录树 使用 Git Trees API 获取文件清单，不逐层遍历所有目录。
4
两轮文件选择 先读取 README、配置和模型入口，再由 AI 指定需要补读的确切文件。
5
形成证据索引 记录 repository、commit、path、symbol 和可用行号。
限制 第一版取值 目的
单文件文本 最多 120 KB 阻止异常大文件占满上下文
单轮文件数 最多 12 个 控制 GitHub 请求和模型输入
单次分析文本 最多 600 KB 保证可预测的资源预算
允许的文件 必须来自固定 commit 的目录树 阻止模型构造任意 URL 或路径
执行能力 无 不执行仓库代码和安装脚本

API 依据： Git Trees、 Repository Contents、 Rate Limits。

06首次生成流程

1
用户提交仓库链接与可选要求 例如“重点展示推理阶段，并标注主要张量尺寸”。
2
固定仓库版本并读取目录树 仓库更新不会改变当前分析中已经读取的代码版本。
3
选择并读取两批关键文件 README、配置、模型入口、模块注册、forward 和推理路径。
4
读取论文最相关的 1–2 个方法章节 arXiv 使用章节读取，普通 PDF 使用章节字符范围。
5
建立论文概念与代码符号映射 区分代码确认、仅论文描述和推断内容。
6
生成、校验并保存网络图 v1 只有图结构和证据均合法才产生版本并替换当前图。

07逐轮优化与版本

每轮以当前图为基线生成“结构化补丁”，避免无关节点被大范围重画。补丁通过校验后物化为完整快照，便于可靠撤销。 

用户选择节点（可选）
  → 输入修改要求
  → 组合当前图、证据索引和最近对话
  → 证据不足时申请读取确切文件
  → AI 返回 message + graphPatch + evidence + warnings
  → 校验节点、连线、证据与无关分支稳定性
  → 生成完整快照 vN
  → 定位到本轮 changedNodeIDs

版本操作

  • 撤销上一版：切换到父版本，不删除后续版本；
  • 恢复最新版：回到最新成功版本；
  • 版本记录：按时间显示用户要求、修改摘要与来源；
  • 设为最终版：复制到当前总览并更新 HTML 附件。

08模型调用契约

Parameters

currentGraph       : 当前网络图，非训练参数
selectedNode       : 用户选中的节点，可为空
userInstruction    : 本轮修改要求
paperEvidence      : 论文方法章节证据
repositoryEvidence : 固定 commit 下的代码证据
recentMessages     : 网络图专用对话摘要与最近消息
modelPreset        : 复用主对话当前模型配置
fileBudget         : 文件数量与文本大小限制，超参数

Data flow

evidenceIndex = map(paperEvidence, repositoryEvidence)
requestScope  = understand(userInstruction, selectedNode)

neededFiles   = choose_missing_evidence(requestScope, evidenceIndex)
newEvidence   = read_allowed_files(neededFiles)
graphPatch    = generate_patch(currentGraph, requestScope, evidenceIndex + newEvidence)
validatedGraph = validate_and_apply(currentGraph, graphPatch)
revision      = save_new_version(validatedGraph, evidenceReferences)

Loss / objective

没有本地训练或新增可学习参数，使用推理时约束目标：

Objective =
    满足用户本轮修改要求
  + 保留无关模块稳定
  + 最大化论文/代码证据覆盖
  + 保持网络图可读性
  - 无依据的架构细节
  - 不必要的节点数量
  - 与本轮无关的大范围重绘

09数据结构

当前最终图继续保存在 OverviewData.networkTopology，以兼容现有渲染和导出；完整工作区另存，避免总览对象无限膨胀。

浏览器 HTML 只包含当前最终图、版本号、仓库 URL、commit SHA、论文章节和代码定位；不包含可编辑对话、历史版本、API 设置或源码正文。

11错误处理与回退

场景 界面行为 数据保证
URL 不合法 在输入框下说明只接受公开 GitHub 仓库 不发出网络请求
仓库不存在或私有 显示“无法公开访问” 保留当前图
GitHub 限流 显示恢复时间，不连续重试 保留输入和缓存
未找到模型实现 列出已经检查的文件，允许补充路径提示 不生成空版本
论文与代码不一致 并列显示差异与各自依据 不把推断标成代码事实
模型返回非法图补丁 显示校验错误 不应用、不产生版本
网络中断 允许重试本轮 当前图和用户输入不丢失
更换仓库 覆盖来源前确认 旧版本仍可查看

12测试图纸与验收标准

单元测试
  • GitHub URL 白名单
  • 固定 commit 与路径校验
  • 文件筛选和资源预算
  • 图补丁与证据校验
  • 版本撤销和恢复
集成测试
  • 公开仓库生成 v1
  • 对话修改生成 v2
  • 按需补读代码
  • 限流和非法图不覆盖
  • WebDAV 恢复版本
DOM 交互测试
  • 重新生成按钮可见性
  • 来源栏与发送状态
  • 选择节点局部优化
  • 图高度跟随 SVG
  • 导出排除编辑对话

完成条件

  1. 用户仅提供公开仓库链接即可生成有代码依据的网络图；
  2. 后续对话只修改网络图，不污染主对话或其他总览栏目；
  3. 每次成功修改均可撤销，任何失败均不覆盖当前图；
  4. 节点依据可以定位到论文章节或固定 commit 下的代码符号；
  5. 图形高度适配实际内容，图下对话不会被大块空白推远；
  6. 跨设备恢复当前图、版本和对话，但不在 WebDAV 中保存源码正文。

13第一版非目标

  • 私有 GitHub 仓库与 GitHub Token 管理；
  • GitLab、Gitee 等其他代码平台；
  • 克隆、执行、编译仓库代码或下载权重；
  • 运行时张量追踪和自动性能分析；
  • 多人同时编辑同一网络图；
  • 自动读取完整主对话；
  • 在导出的浏览器 HTML 中继续调用 AI。
第一版成功的核心不是“读取尽可能多的代码”，而是用有限、可追溯的论文和代码证据，稳定地产生可以逐步改进的网络图。
