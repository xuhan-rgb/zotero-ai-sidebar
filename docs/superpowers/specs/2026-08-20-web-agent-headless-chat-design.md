# Web Agent 可见配置与无窗口对话设计

## 目标

账号配置期间允许用户看到专用 Chrome；启用“对话时在后台隐藏浏览器”后，网页问答必须使用 Headless Chrome，上传附件、提交和生成期间都不能创建、恢复或聚焦桌面窗口。

## 生命周期

- `visible`：仅供账号配置或用户明确取消隐藏选项时使用。
- `headless`：默认网页问答模式，使用同一专用用户配置目录以复用登录状态。
- `stopped`：账号配置点击“完成并隐藏”后关闭可见 Chrome；直到下一条网页任务才按需启动 Headless Chrome。

切换模式时先通过 CDP 关闭现有 Chrome，等待调试端点退出并清除旧连接，再以目标模式启动。不同模式不得同时打开同一用户配置目录。

## 数据流

1. 账号按钮请求 `visible` 模式，必要时关闭 Headless Chrome并启动可见 Chrome。
2. 用户完成账号配置且勾选隐藏后，Agent 读取登录状态并关闭可见 Chrome。
3. 隐藏网页任务请求 `headless` 模式，按需启动后执行页面导航、附件上传、提交和答案同步。
4. 明确取消隐藏的网页任务请求 `visible` 模式，并允许窗口聚焦。

## 故障处理

- Chrome 关闭或启动超时应使当前操作失败并返回明确错误，不能同时启动第二个实例。
- Agent 重启后通过浏览器运行时信息识别现有实例模式，不能只依赖内存标志。
- 模式切换会清空页面会话缓存；材料可能重新上传，但不得重复提交问题。

## 验收

- 隐藏任务的 Chrome 进程包含 Headless 参数，且任务路径不调用窗口恢复或聚焦。
- 账号配置使用可见 Chrome；关闭配置后可见 Chrome 退出。
- 两种模式共用登录配置目录且从不并存。
- 现有附件上传、窗口设置、任务发送相关测试通过，插件和 Web Agent 构建/安装通过。
