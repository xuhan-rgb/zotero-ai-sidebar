视觉规格

  • “已就绪……”保持在对话区域顶部，不随签名移动。
  • 两条提醒组成一个签名组，放在剩余对话内容区域的水平、垂直中心。
  • 两行采用相同字号、行高和短横引导，通过间距区分，不使用粗体抢占注意力。
  • 鼠标悬停或键盘聚焦签名组时，右侧显示关闭按钮 ×。
  • 字号 12px，普通字形，不使用中文斜体。
  • 使用次要文字颜色，不添加卡片、边框或阴影。
  • 显示前缀“——”，正文由用户配置。
  • 最大宽度跟随消息区域，长文本自然换行。
  • 字段为空时不渲染节点，也不留下额外空白。

配置规则

  • 使用多行列表配置签名，每行一条，并支持添加、删除、上移和下移。
  • 按列表顺序逐行显示，不随机轮播；每条最多 80 个字符。
  • 旧版英文分号 ; 或中文分号 ； 内容在读取时自动拆分为列表。
  • 迁移时去除每条签名首尾空格，并忽略连续分号产生的空项。
  • 修改后自动保存，与昵称和头像行为一致。
  • 关闭按钮与设置页复选框控制同一个持久化开关，不清空签名文本。
  • 默认签名仅在配置项从未存在时初始化一次，插件升级不得覆盖已有值。
  • 用户主动清空签名也属于有效配置，升级后必须继续保持为空。
  • 跟随设置导出、导入和 WebDAV 状态同步。
  • 默认配置包含两条列表项；用户可以增删、修改或调整任意一条的顺序。
  • 不支持随机轮播，保持阅读顺序和界面位置稳定。

显示状态流

1. 打开空对话 没有用户消息、真实 AI 回答或恢复任务时，显示欢迎语和签名。
2. 用户点击发送 第一条消息进入本地状态后立即隐藏，不等待模型开始回答。
3. 对话持续 API 流式回答、WEB 增量同步和历史恢复期间都不再显示。
4. 清空或新建 切换到新的空对话或清空当前对话后，重新显示签名。

数据边界

保存位置UI 设置；可随配置备份和 WebDAV 设置同步。
默认值初始化仅当签名配置键不存在时写入；已有文本或显式空值均原样保留。
版本升级不根据版本号重写签名，不用新的默认文案替换用户配置。
模型请求不发送给 API、ChatGPT、DeepSeek 或自定义网页。
聊天记录不创建助手消息，不写入历史或对话分支。
导出与笔记不进入 Markdown、复制内容、Zotero 笔记或 PDF。
Token纯本地渲染，不占用任何模型 token。

验收标准

  • 空对话显示欢迎语和非空签名。
  • 第一条用户消息发送后立即隐藏。
  • API、WEB、历史恢复和会话切换行为一致。
  • 已有历史的会话从不显示签名。
  • 清空会话或新建空会话后重新显示。
  • 留空配置不产生额外布局空间。
  • 升级前修改过的签名在升级后保持完全一致。
  • 升级前主动清空或关闭签名，升级后仍保持清空或关闭状态。
  • 只有全新安装或确实缺少配置键时才采用当前默认签名。
  • 导出、同步、复制和模型请求遵守数据边界。
  • 不修改 AI 流式刷新与 WEB 增量同步链路。

不采用的方案

不建议使用带背景的签名卡片，也不建议配置多条签名随机轮播。卡片会与进度卡、上下文卡竞争视觉层级；随机签名则增加存储、同步和测试复杂度，并削弱界面的稳定感。
